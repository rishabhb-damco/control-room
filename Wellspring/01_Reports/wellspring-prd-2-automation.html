Automation engine

A HubSpot/Zapier-style rules engine: every rule is Trigger → Condition → Action, evaluated by an event-driven worker, with every firing logged for audit and every action idempotent (re-running a rule against the same state never double-fires an email or double-creates a task).

Event source
record change · stage move · cron tick · sync write
→
Rule matcher
filters rules by event type
→
Condition evaluator
field comparisons, time-since, counts
→
Action executor
create task · notify · change field · webhook
→
Rule Fire Log
rule_id, entity_id, fired_at, outcome
Trigger typeExamples
Record eventlead.created, lead.field_changed, lead.stage_changed, task.overdue
Time-based (cron)Runs every 15 min checking "time since X" conditions (e.g. no activity in 24h); daily/weekly digest jobs
Sync eventsheet.row_added, sheet.row_updated, sync.conflict_detected
Manual triggerStaff-initiated action that also satisfies an automation condition (e.g. logging a "Reached" call outcome)

Admin control: every rule below ships enabled by default but can be toggled off, or have its thresholds (hours, attempt counts) edited, from Settings → Pipeline Config → Automation. Disabling a rule does not delete its fire history.
